# 链接图像颜色过滤Bug修复

## 问题描述

链接图像（特别是PSD文件）在分色预览模式下，即使所有颜色通道都被关闭，仍然会显示图像。这表明链接图像没有接受颜色过滤的控制。

## 根本原因

问题出在 `src/core/evaluator.js` 中的缓存机制：

1. **首次加载**：链接图像第一次加载时没有 `colorFilterConfig`，图像被缓存
2. **切换分色预览**：当用户切换分色预览时，虽然 `colorFilterConfig` 被正确传递，但在 `OPS.paintXObject` 处理中：
   - 第1845-1850行：从本地缓存中检查并返回缓存的图像
   - 第1861-1869行：从全局缓存中检查并返回缓存的图像
   - **问题**：这些缓存检查发生在调用 `buildPaintImageXObject` 之前，导致使用了旧的（未应用颜色过滤的）缓存图像

## 修复方案

在使用缓存之前检查是否存在 `colorFilterConfig`：

### 修改位置1：本地缓存检查（第1844-1851行）

```javascript
if (isValidName) {
  // 注意：当colorFilterConfig存在时，跳过本地缓存检查
  // 这样可以确保使用新的颜色过滤配置重新生成图像
  if (!colorFilterConfig) {
    const localImage = localImageCache.getByName(name);
    if (localImage) {
      addCachedImageOps(operatorList, localImage);
      args = null;
      continue;
    }
  }
}
```

### 修改位置2：全局缓存检查（第1860-1869行）

```javascript
if (xobj instanceof Ref) {
  // 注意：当colorFilterConfig存在时，跳过缓存检查
  // 这样可以确保使用新的颜色过滤配置重新生成图像
  if (!colorFilterConfig) {
    const cachedImage =
      localImageCache.getByRef(xobj) ||
      self._regionalImageCache.getByRef(xobj) ||
      self.globalImageCache.getData(xobj, self.pageIndex);
    if (cachedImage) {
      addCachedImageOps(operatorList, cachedImage);
      resolveXObject();
      return;
    }
  }

  xobj = xref.fetch(xobj);
}
```

## 技术细节

- 当 `colorFilterConfig` 存在时，跳过所有缓存检查
- 这确保图像会经过完整的 `buildPaintImageXObject` 流程
- `buildPaintImageXObject` 内部已经有类似的缓存跳过逻辑（第800行）
- 现在整个处理链路都正确处理了颜色过滤配置

## 测试

1. 打开包含链接图像（PSD文件）的PDF
2. 切换分色预览模式
3. 关闭所有颜色通道
4. 验证链接图像正确消失

## 影响范围

- 只影响存在 `colorFilterConfig` 时的图像处理
- 正常情况下（无颜色过滤）仍使用缓存，保持性能
- 适用于所有类型的XObject图像（包括链接图像）
