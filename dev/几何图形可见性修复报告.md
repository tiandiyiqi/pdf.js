## 问题总结

### 症状

用户使用几何形状工具（矩形、圆形、箭头）绘制时，虽然操作正常，但**绘制的图形在页面上完全不可见**。

### 根本原因

**DrawLayer 的 parent 容器设置不正确**，导致 SVG 元素被添加到错误的 DOM 位置。

#### 详细分析

1. **初始设置**（在 `pdf_page_view.js:1166`）

   ```javascript
   this.drawLayer.setParent(canvasWrapper);
   ```

   DrawLayer 的 parent 被设置为 `canvasWrapper`

2. **传递给 AnnotationEditorLayer**（在 `pdf_page_view.js:1180`）

   ```javascript
   drawLayer: this.drawLayer.getDrawLayer();
   ```

   DrawLayer 实例被传递给 AnnotationEditorLayer

3. **问题发生**
   - 当几何编辑器调用 `parent.drawLayer.draw()` 时
   - DrawLayer 在 `#createSVG()` 中执行 `this.#parent.append(svg)`
   - SVG 被添加到 `canvasWrapper`
   - **但是编辑器的 div 在 `annotationEditorLayer` 中**
   - 两者不在同一个父容器，导致 SVG 和编辑器 div 的定位无法对齐
   - 结果：SVG 元素虽然存在，但位置错误或被裁剪，用户看不见

---

## 修复方案

### 核心修复：重新设置 DrawLayer parent

**文件**: `src/display/editor/annotation_editor_layer.js`  
**位置**: 构造函数中，在保存 drawLayer 引用之后

```javascript
// 确保 DrawLayer 的 parent 指向编辑器层 div，这样 SVG 元素会被添加到正确的容器
if (this.drawLayer) {
  this.drawLayer.setParent(this.div);
}
```

**原理**:

- AnnotationEditorLayer 在初始化时，将 DrawLayer 的 parent 从 `canvasWrapper` 更新为 `this.div`（编辑器层容器）
- DrawLayer.setParent() 会自动处理已有的 SVG 元素，将它们移动到新的父容器
- 之后创建的所有 SVG 元素都会被添加到编辑器层，与编辑器 div 在同一个父容器下
- SVG 和编辑器 div 的百分比定位能够正确对齐

### 辅助修复：最小尺寸保护

**文件**: `src/display/editor/geoshape.js`  
**位置**: `#updateBbox()` 方法

```javascript
// 确保最小尺寸，防止尺寸为 0
const minSize = 0.001;
[this.x, this.y, this.width, this.height] = [
  x,
  y,
  Math.max(width, minSize),
  Math.max(height, minSize),
];
```

**原理**:

- 防止在拖动距离极小时，width 或 height 为 0
- 确保 SVG 元素和编辑器 div 始终有非零尺寸

## 风险评估

### 低风险 ✅

**理由**:

1. **修改最小化**: 只添加了一行核心代码 `drawLayer.setParent(this.div)`
2. **API 已有支持**: `setParent()` 方法已存在，专门用于处理 parent 更新
3. **自动迁移**: 已有的 SVG 元素会自动移动到新 parent
4. **条件日志**: 调试日志使用条件编译，不影响生产性能
5. **向后兼容**: DrawingEditor 等其他工具不受影响，因为它们不依赖 DrawLayer parent 的具体值

### 潜在影响

1. **DrawingEditor**: 也使用 DrawLayer，需要验证其正常工作
   - **缓解**: 已添加到回归测试清单
   - **风险**: 低（DrawingEditor 在编辑器层内创建，逻辑一致）

2. **性能**: setParent 会移动已有 SVG
   - **缓解**: 初始化时 DrawLayer 通常没有 SVG，无需移动
   - **风险**: 低（即使移动也是 DOM 操作，性能影响可忽略）

3. **多页面场景**: 每个页面有独立的 DrawLayer 和 AnnotationEditorLayer
   - **缓解**: pageIndex 隔离，不会互相影响
   - **风险**: 低
