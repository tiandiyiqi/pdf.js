# 🎯 图像颜色过滤 - 所有Bug修复完整总结

## 📊 发现并修复的4个Bug

### Bug #1：CMYK图像通道过滤导致整个图像消失

**原因**：使用了错误的API（`Map.get()` 返回 `undefined`）

**位置**：`src/core/icc_colorspace.js` 第228-233行

**修复**：使用 `colorFilterConfig.isVisible()` 方法

**影响**：所有ICC-based CMYK图像

---

### Bug #2：DeviceCMYK快速路径跳过颜色过滤

**原因**：JPEG解码器直接转换CMYK→RGB，跳过了 `fillRgb()`

**位置**：`src/core/image.js` 第858行

**修复**：注释掉 `DeviceCMYK` 快速路径，让CMYK走正常流程

**影响**：

- JPEG压缩的CMYK图像
- 需要降采样的大图像

---

### Bug #3：调试日志残留

**原因**：`AlternateCS.getRgbItem()` 中的 `console.log` 输出

**位置**：`src/core/colorspace.js` 第499-504行

**修复**：删除 `console.log` 语句

**影响**：性能和日志清洁度

---

### Bug #4：链接图像/大图像使用ImageDecoder跳过颜色过滤 ⭐ 关键

**原因**：原生图像解码器（`getTransferableImage()`）直接输出bitmap，完全跳过PDF.js的颜色空间系统

**位置**：`src/core/image.js` `#getImage()` 方法（第1046行）

**修复**：当启用颜色过滤时，对CMYK和专色图像禁用原生解码

**影响**：

- 链接JPEG图像（你报告的问题！）
- 大尺寸JPEG图像
- 使用浏览器ImageDecoder解码的所有CMYK图像

---

## 🔍 Bug #4 详细说明

### 问题本质

```
链接图像（JPEG）
  ↓
浏览器ImageDecoder（硬件加速）
  ↓
直接输出RGB bitmap
  ↓
❌ 跳过了PDF.js的颜色空间转换
❌ 跳过了colorSpace.fillRgb()
❌ 跳过了颜色过滤
```

### 为什么会这样？

1. **性能优化**：浏览器的ImageDecoder比JavaScript快得多
2. **快速路径**：PDF.js为性能优化添加了这个路径
3. **副作用**：但这个路径跳过了PDF.js的颜色管理系统

### 受影响的图像类型

- ✅ **链接JPEG图像**（你报告的！）
- ✅ **大尺寸JPEG图像**（通常使用ImageDecoder）
- ✅ **某些嵌入JPEG图像**（取决于浏览器和图像大小）

### 修复代码

```javascript
async #getImage(width, height) {
  // 如果启用了颜色过滤，禁用原生解码（ImageDecoder）
  // 因为原生解码跳过了PDF.js的颜色空间转换系统，无法应用颜色过滤
  if (this.colorFilterConfig && this.colorFilterConfig.enabled) {
    const needsColorFiltering =
      this.colorSpace.name === "DeviceCMYK" ||
      this.colorSpace.name === "Alternate";

    if (needsColorFiltering) {
      return null; // 强制走fillRgb()流程
    }
  }

  // 原有逻辑...
  const bitmap = await this.image.getTransferableImage();
  // ...
}
```
