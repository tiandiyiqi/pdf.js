# 分页颜色过滤完整修复

## 问题描述

### 原始问题

当油墨列表的清单变化触发颜色过滤功能时，系统执行了全局渲染而非仅当前页面的局部渲染。

### v1 修复后的问题

1. 点击第1页关闭Cyan后，整个页面消失，再也点不出来
2. 切换到第2页时，第1页又出现了

### v2 修复后的问题

点击关闭C后，页面没有立即重新渲染，需要切换到第2页，第1页才显示出来

### 根本原因

#### 问题1：全局刷新

`pdf_viewer.js` 中的 `colorFilterConfigPromise` setter 调用 `this.refresh()` 刷新所有页面。

#### 问题2：全局配置影响所有页面

所有页面共享同一个 `ColorFilterConfig` 实例和同一个 `Promise`：

- 用户在第1页关闭Cyan → 更新全局 `ColorFilterConfig`
- 触发事件，传递 `Promise.resolve(this._colorFilterConfig)`
- `PDFPageView` 通过比较 `previousPromise !== colorFilterConfigPromise` 来判断是否重新渲染
- 但是每次都是**同一个已解决的 Promise**，导致页面不会重新渲染！
- 即使重新渲染，所有页面都使用同一个全局配置，导致第1页的设置影响第2页

#### 问题3：页面不会立即渲染

- `PDFPageView.update()` 调用 `reset()` 重置页面状态
- 但 `reset()` 只是将 `renderingState` 设置为 `INITIAL`
- 真正的渲染需要等待 `PDFViewer.update()` 检查可见页面
- 如果不主动调用，页面会等到下次滚动或页面切换时才渲染

## 完整修复方案

### 修复1：只刷新当前页面并立即渲染

**文件**：`web/pdf_viewer.js`  
**位置**：`set colorFilterConfigPromise()` 方法（第2071-2088行）

```javascript
set colorFilterConfigPromise(promise) {
  if (!(promise instanceof Promise)) {
    throw new Error(`Invalid colorFilterConfigPromise: ${promise}`);
  }
  if (!this.pdfDocument) {
    return;
  }
  this._colorFilterConfigPromise = promise;

  // 只刷新当前页面，避免全局刷新导致闪烁
  const currentPageView = this._pages[this._currentPageNumber - 1];
  if (currentPageView) {
    currentPageView.update({ colorFilterConfigPromise: promise });
    // 立即触发渲染，确保页面立即更新
    this.update();
  }
}
```

**关键点**：

1. 只更新当前页面，不是所有页面
2. **立即调用 `this.update()`** 触发渲染，确保页面立即显示变化

### 修复2：为每个页面创建独立的ColorFilterConfig

**文件**：`web/pdf_ink_list_viewer.js`

#### 2.1 添加 `_triggerCurrentPageColorFilter()` 方法

**位置**：第205-246行

```javascript
/**
 * 触发当前页面的颜色过滤更新
 * 基于当前页面的可见性状态创建一个新的ColorFilterConfig
 */
_triggerCurrentPageColorFilter() {
  // 基于当前页面的可见性状态创建一个新的ColorFilterConfig
  const pageConfig = new ColorFilterConfig();
  const pageVisibilityState = this._getPageVisibilityState(this.currentPageNumber);

  // 初始化CMYK通道
  const channelNameMap = {
    青色: "Cyan",
    洋红色: "Magenta",
    黄色: "Yellow",
    黑色: "Black",
  };

  for (const [chineseName, englishName] of Object.entries(channelNameMap)) {
    const visible = this._getInkVisibility(this.currentPageNumber, chineseName, true);
    pageConfig.setVisibility(englishName, visible);
  }

  // 初始化专色
  const currentState = this.pageColorStates.get(this.currentPageNumber);
  if (currentState && currentState.colors) {
    for (const colorInfo of currentState.colors) {
      const visible = this._getInkVisibility(
        this.currentPageNumber,
        colorInfo.name,
        true
      );
      pageConfig.setVisibility(colorInfo.name, visible);
    }
  }

  // 触发 colorfilterconfig 事件，传递新的Promise
  console.log(
    `[PDFInkListViewer] 触发页面${this.currentPageNumber}的颜色过滤更新`
  );
  this.eventBus.dispatch("colorfilterconfig", {
    source: this,
    promise: Promise.resolve(pageConfig), // 每次都创建新的Promise
  });
}
```

**关键点**：

1. 每次调用都创建一个**新的** `ColorFilterConfig` 实例
2. 从当前页面的持久化状态（`inkVisibilityState`）恢复可见性
3. 创建**新的 Promise**，这样 `PDFPageView` 才能检测到变化并重新渲染

#### 2.2 修改所有触发颜色过滤的地方

替换所有的：

```javascript
this.eventBus.dispatch("colorfilterconfig", {
  source: this,
  promise: Promise.resolve(this._colorFilterConfig),
});
```

为：

```javascript
this._triggerCurrentPageColorFilter();
```

**修改的方法**：

1. `_showAllInks()` - 全部显示
2. `_hideAllInks()` - 全部隐藏
3. `_createInkElement()` 中的 CMYK 组点击事件
4. `_createInkElement()` 中的单个颜色点击事件

## 工作原理

### 数据流

```
用户点击颜色
  ↓
更新当前页面的持久化状态 (inkVisibilityState)
  ↓
调用 _triggerCurrentPageColorFilter()
  ↓
基于当前页面状态创建新的 ColorFilterConfig
  ↓
创建新的 Promise.resolve(pageConfig)
  ↓
触发 colorfilterconfig 事件
  ↓
pdf_viewer.js 的 setter 被调用
  ↓
只更新当前页面的 colorFilterConfigPromise
  ↓
PDFPageView 检测到 Promise 变化（previousPromise !== newPromise）
  ↓
清除缓存并重新渲染当前页面
```

### 关键设计

1. **每个页面独立的 ColorFilterConfig**
   - 不是在类中维护多个实例
   - 而是每次需要时，基于当前页面状态**动态创建**

2. **每次都是新的 Promise**
   - 不能复用 `Promise.resolve(config)`，因为返回的是同一个已解决的 Promise
   - 必须每次都调用 `Promise.resolve(new ColorFilterConfig())`

3. **持久化状态按页面存储**
   - `inkVisibilityState` 已经是 `Map<pageNumber, Map<inkName, visible>>`
   - 每个页面的可见性独立保存和恢复

4. **局部渲染**
   - 只刷新当前页面，不影响其他页面
   - 页面切换时，新页面从自己的持久化状态恢复

## 技术要点

### 为什么每次创建新的 ColorFilterConfig？

1. **Promise 引用比较**：`PDFPageView` 通过比较 Promise 引用来判断是否需要重新渲染
2. **避免共享状态**：不同页面的配置互不影响
3. **按需创建**：只在需要时创建，不占用额外内存

### 为什么不在类中维护页面配置Map？

1. **更简单**：不需要管理 Map 的生命周期
2. **更灵活**：配置总是最新的，直接从持久化状态读取
3. **更可靠**：避免配置和持久化状态不同步的问题

### 持久化状态是如何工作的？

- `inkVisibilityState` 是 `Map<pageNumber, Map<inkName, visible>>`
- 用户点击颜色时，更新 `inkVisibilityState[currentPageNumber][inkName]`
- 页面切换时，从 `inkVisibilityState[newPageNumber]` 恢复油墨列表UI
- 颜色过滤时，从 `inkVisibilityState[currentPageNumber]` 创建 `ColorFilterConfig`
