# PDF.js 颜色转换与透明度混合开发计划

基于《PDF.js渲染流程与颜色处理分析》文档，本计划旨在解决当前 CMYK 颜色空间转换与透明度混合顺序不当的问题，特别是 CMYK + 多专色（DeviceN）场景下的通道信息丢失问题。

## 项目背景

### 典型应用场景

考虑一个专业 PDF 文件，包含：

- **颜色空间**：DeviceN [Cyan Magenta Yellow Black Spot1 Spot2 Spot3 ...]（CMYK + 多个专色）
- **图层结构**：多个预览图层，每个图层包含页面大小矩形
- **填充内容**：
  - 图层1：100% Cyan
  - 图层2：100% Spot1
  - 图层3：DeviceN [Cyan Spot1]（Cyan + Spot1 组合）
- **透明度设置**：所有矩形设置透明度和混合模式（如 Lighten 模式）

**关键要求**：在图层合并前，各颜色通道必须保持独立，不能有任何 RGB 转换参与中间计算过程。

### 当前问题分析

根据《PDF.js渲染流程与颜色处理分析》文档，当前实现存在以下问题：

#### 问题1：CMYK 颜色转换过早

- **位置**：`src/core/evaluator.js:2055-2064`
- **问题**：CMYK 颜色在解析阶段就被转换为 RGB
- **影响**：丢失 CMYK 通道信息，无法在 CMYK 空间进行混合
- **示例**：100%K（黑色）与 100%C（青色）在 Lighten 模式下，应该显示白色，但实际显示青色

#### 问题2：DeviceN 专色通道信息丢失（严重问题）

- **位置**：
  - `src/core/colorspace.js:357-367` (AlternateCS.getRgbItem)
  - `src/core/evaluator.js:2073-2079` (DeviceN/ColorN → RGB 转换)
- **问题**：DeviceN 色彩空间中的专色通道在色调函数转换时被合并到基础颜色空间
- **流程**：
  ```
  DeviceN [Cyan Spot1 Spot2] (3通道)
      ↓ 色调函数转换
  CMYK (4通道) - 专色通道被合并
      ↓ CMYK → RGB 转换
  RGB (3通道) - 专色通道信息完全丢失 ⚠️⚠️
  ```
- **影响**：
  - 无法单独预览 Spot1、Spot2 等专色通道
  - 无法实现专业预览功能
  - 混合模式在 RGB 空间计算，语义错误

#### 问题3：混合模式映射不当

- **位置**：`src/core/evaluator.js:122-181` (normalizeBlendMode)
- **问题**：PDF Lighten 直接映射到 Canvas lighten
- **影响**：Canvas lighten 在 RGB 空间工作，无法实现 CMYK Lighten 的语义

#### 问题4：颜色空间信息未传递

- **位置**：`src/display/canvas.js` 整个渲染流程
- **问题**：渲染时无法访问原始颜色空间信息
- **影响**：无法根据颜色空间选择正确的混合算法

#### 问题5：多专色场景处理不足

- **位置**：`src/core/colorspace.js:349-419` (AlternateCS类)
- **问题**：不支持 CMYK + 多个专色的复杂 DeviceN 场景
- **影响**：
  - 无法处理 CMYK + 5 专色等复杂场景
  - 无法实现通道级别的独立混合
  - 专业预览功能完全失效

## 开发目标

### 核心需求

针对 CMYK + 多专色透明度混合场景，实现无 RGB 转换的完整解决方案：

```
PDF 内容流 (DeviceN [Cyan Magenta Yellow Black Spot1 Spot2 ...])
    ↓
[阶段1] 操作符解析 (evaluator.js)
    ↓ 保留所有颜色通道原始值
    - CMYK通道: [C, M, Y, K]
    - 专色通道: [Spot1, Spot2, Spot3, ...]
    - 完整DeviceN信息: [C, M, Y, K, Spot1, Spot2, ...]
操作符列表 (包含完整DeviceN颜色信息)
    ↓
[阶段2] 图层分离与颜色空间确定
    ↓ 识别预览图层，保持各通道独立性
    - 识别预览图层结构
    - 确定混合颜色空间（可能是DeviceN本身）
    - 保持通道分离状态
[阶段3] 原始颜色空间透明度混合
    ↓ 通道级独立混合
    - Cyan通道: Cyan → Cyan 混合
    - Magenta通道: Magenta → Magenta 混合
    - Yellow通道: Yellow → Yellow 混合
    - Black通道: Black → Black 混合
    - Spot1通道: Spot1 → Spot1 混合（独立）
    - Spot2通道: Spot2 → Spot2 混合（独立）
    - ... 每个专色通道独立处理
[阶段4] 图层合并（无RGB参与）
    ↓ 在原始颜色空间中进行图层合成
    - 在DeviceN空间中进行图层合成
    - 保持各通道的独立性
    - 支持专业预览功能（单通道、多通道预览）
[阶段5] 最终输出（可选转换）
    ↓ 仅在需要显示时考虑转换
    - 预览模式: 保持DeviceN格式，支持通道分离显示
    - 显示模式: 可选转换为RGB用于屏幕显示
    - 输出模式: 保持DeviceN格式用于专业输出
最终输出 (保持原始颜色通道完整性)
```

### 关键原则

1. **通道独立性**：每个颜色通道（C、M、Y、K 及各个专色）在混合过程中保持完全独立
2. **无RGB强制转换**：任何阶段都不强制进行RGB转换，包括中间计算过程
3. **DeviceN支持**：正确处理DeviceN色彩空间（如Cyan+Spot1组合），支持任意数量的专色通道
4. **图层预览**：支持专业预览功能，可单独查看各颜色通道效果
5. **混合模式保真**：在原始颜色空间中实现PDF标准混合模式，每个通道独立计算

## 解决方案架构

基于《PDF.js渲染流程与颜色处理分析》文档中的四个解决方案，本项目采用**方案4：DeviceN 多通道独立处理**作为核心方案，并结合其他方案的优势：

### 核心方案：DeviceN 多通道独立处理

**适用场景**：CMYK + 多专色场景（DeviceN色彩空间）

**关键技术点**：

1. **多通道数据结构**：

   ```javascript
   // 扩展颜色值存储
   {
     colorSpace: 'DeviceN',
     channels: {
       cmyk: [C, M, Y, K],
       spots: {
         'Spot1': value1,
         'Spot2': value2,
         // ... 任意数量的专色
       }
     }
   }
   ```

2. **通道级混合算法**：

   ```javascript
   // DeviceN Lighten 模式示例
   function deviceNLighten(channel1, channel2) {
     // 每个通道独立计算
     return {
       cmyk: lightenCMYK(channel1.cmyk, channel2.cmyk),
       spots: lightenSpots(channel1.spots, channel2.spots),
     };
   }
   ```

3. **预览图层识别**：
   - 识别专业预览图层结构
   - 保持通道分离状态
   - 支持通道选择性显示

### 辅助方案：延迟颜色转换（方案1）

**适用场景**：纯 CMYK 场景（无专色）

**思路**：

- 在解析阶段保留 CMYK 原始值
- 在渲染阶段，根据混合颜色空间决定何时转换
- 如果混合颜色空间是 CMYK，则在 CMYK 空间混合后再转换

### 辅助方案：自定义混合实现（方案2）

**适用场景**：CMYK 混合模式实现

**思路**：

- 检测 CMYK 颜色空间和 Lighten 模式
- 使用 Canvas 的 `getImageData` 和 `putImageData` 手动实现 CMYK Lighten
- 在像素级别进行混合计算

### 辅助方案：使用混合颜色空间（方案3）

**适用场景**：根据 PDF 规范确定混合颜色空间

**思路**：

- 检测 PDF 的混合颜色空间设置
- 如果混合颜色空间是 CMYK，使用方案2
- 如果混合颜色空间是 RGB，使用当前流程

### 关键技术挑战

1. **DeviceN色彩空间复杂性**
   - 处理CMYK+多专色的DeviceN色彩空间，保持各通道完全独立
   - 支持任意数量的专色通道（1-10+）
   - 实现通道级独立混合

2. **多通道混合算法**
   - 在原始颜色空间中实现C、M、Y、K及各个专色通道的独立混合
   - PDF标准混合模式在DeviceN空间的实现
   - 性能优化：CMYK+5专色等复杂场景

3. **预览图层识别**
   - 准确识别专业预览图层，确保通道分离状态不被破坏
   - 支持用户自定义预览模式
   - 图层结构分析算法

4. **性能与精度平衡**
   - 在处理CMYK+5专色等复杂场景时保持高性能
   - 通道级并行处理
   - 内存优化：多通道数据结构优化

5. **Canvas输出限制**
   - HTML5 Canvas原生不支持DeviceN色彩空间
   - 需要创新的输出方案：像素级操作、多通道纹理映射
   - 预览模式vs显示模式的切换

6. **向后兼容性**
   - 确保无RGB转换功能与现有PDF.js生态系统兼容
   - RGB场景：保持现有流程
   - CMYK场景：延迟转换，不影响现有功能
   - DeviceN场景：新增功能，可选启用

## 风险评估与应对

### 高风险项

1. **DeviceN色彩空间处理失败**
   - **风险**：CMYK+多专色的DeviceN色彩空间无法正确处理，通道信息丢失
   - **应对**：
     - 建立DeviceN色彩空间验证机制
     - 针对Cyan+Spot1等组合进行专项测试
     - 分阶段实现，先支持基础DeviceN场景
     - 建立测试基准和验证工具

2. **多通道混合算法复杂性**
   - **风险**：CMYK+5专色等复杂场景下，多通道独立混合算法性能下降
   - **应对**：
     - 优化多通道算法，使用SIMD等并行计算技术
     - 实现通道级别的并行处理
     - 提供性能降级选项
     - 建立性能基准和监控

3. **预览图层识别错误**
   - **风险**：无法准确识别专业预览图层，导致通道分离失败
   - **应对**：
     - 建立图层识别规则库
     - 支持用户自定义预览模式
     - 实现图层结构分析算法
     - 建立验证机制

4. **Canvas DeviceN输出限制**
   - **风险**：HTML5 Canvas不支持DeviceN直接输出，预览功能受限
   - **应对**：
     - 开发多通道纹理映射方案
     - 实现像素级操作方案
     - 提供专用输出插件
     - 支持预览模式vs显示模式切换

5. **专业混合模式实现失败**
   - **风险**：变亮等专业混合模式在DeviceN空间中无法实现
   - **应对**：
     - 研究PDF标准在DeviceN空间的混合算法
     - 提供参考实现
     - 建立测试用例验证正确性
     - 分阶段实现，先支持基础混合模式

### 中等风险项

1. **内存使用变化**
   - **风险描述**：多通道混合算法可能增加内存开销，特别是CMYK+5专色场景
   - **应对策略**：
     - 实现智能内存管理，按需要分配通道内存
     - 优化多通道数据结构设计，避免冗余存储
     - 提供内存使用监控和调优选项
     - 实现通道数据压缩存储
     - 建立内存使用基准

2. **算法复杂性增加**
   - **风险描述**：DeviceN色彩空间处理算法复杂度高，混合模式实现困难
   - **应对策略**：
     - 分阶段实现，先支持基础DeviceN场景
     - 充分测试验证算法正确性，建立测试基准
     - 建立算法性能基准和监控
     - 参考PDF标准实现混合模式算法
     - 代码审查和重构

3. **多通道性能优化**
   - **风险描述**：复杂DeviceN场景（如CMYK+5专色）可能导致性能下降
   - **应对策略**：
     - 实现通道级别的并行处理
     - 优化混合算法的时间复杂度
     - 提供性能降级选项
     - 实现渐进式渲染支持
     - 建立性能基准和优化目标

4. **向后兼容性**
   - **风险描述**：新功能可能影响现有RGB/CMYK场景的兼容性
   - **应对策略**：
     - RGB场景：保持现有流程不变
     - CMYK场景：延迟转换，不影响现有功能
     - DeviceN场景：新增功能，可选启用
     - 充分的回归测试
     - 版本控制和回退机制

## 总结

本开发计划基于《PDF.js渲染流程与颜色处理分析》文档，针对专业PDF预览的核心需求：在CMYK+多专色场景下实现无RGB转换的颜色处理。通过分阶段实施，确保在图层合并前保持各颜色通道的完全独立性，实现真正的专业级预览功能。

### 核心创新点

1. **DeviceN色彩空间完整支持**：支持CMYK+任意数量专色的复杂色彩空间
2. **多通道独立混合**：C、M、Y、K及各专色通道在混合过程中保持独立
3. **专业预览功能**：可单独查看Cyan、Spot1等各个颜色通道的效果
4. **无RGB强制转换**：从解析到输出的完整管线中避免任何RGB中间转换
5. **向后兼容**：RGB场景保持现有流程，不影响现有功能

### 技术突破

- **图层识别技术**：自动识别专业预览图层，确保通道分离
- **DeviceN混合算法**：在原始色彩空间中实现PDF标准混合模式
- **多通道输出方案**：解决HTML5 Canvas对DeviceN色彩空间的限制
- **性能优化策略**：在复杂场景（CMYK+5专色）下保持高性能
