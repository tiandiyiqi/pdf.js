
## 🎯 关键信息点

### 1. 颜色空间类型

日志会显示：

- **DeviceCMYK** - 标准CMYK
- **DeviceRGB** - RGB颜色
- **DeviceGray** - 灰度
- **Separation** - 专色
- **DeviceN** - 多通道专色

### 2. 是否创建ColorValue

如果看到：

```
[DEBUG] setFillColor: Creating CMYK ColorValue
[DEBUG] Created CMYK ColorValue: ...
```

说明我们的新逻辑被触发了。

如果看到：

```
[DEBUG] setFillColor: Using old logic for ...
```

说明使用了旧的直接转RGB逻辑。

### 3. Canvas接收到什么

如果看到：

```
[DEBUG canvas.js] setFillRGBColor received: object
[DEBUG canvas.js] Detected ColorValue object: CMYK
```

说明ColorValue被成功传递到canvas.js。

如果看到：

```
[DEBUG canvas.js] setFillRGBColor received: string
[DEBUG canvas.js] Using old RGB logic
```

说明canvas.js接收到的是普通RGB字符串。

## 🐛 可能的情况分析

### 情况1: 没有看到任何[DEBUG]日志

**原因**:

- 浏览器缓存没有清除
- ServiceWorker缓存
- 新代码没有加载

**解决**:

1. 完全关闭浏览器
2. 重新打开浏览器
3. 访问 http://localhost:8888/web/viewer.html

### 情况2: 看到"Using old logic for DeviceCMYK"

**原因**: 颜色空间检测条件没有匹配

**需要信息**:

- 完整的日志输出
- `cs.name`的实际值

### 情况3: 看到"Creating CMYK ColorValue"但颜色还是错误

**原因**: ColorValue的toRGB()转换可能有问题

**需要信息**:

- "Created CMYK ColorValue"后面的RGB值是什么
- 期望的RGB值是什么

### 情况4: 看到ColorValue创建但canvas.js收到string

**原因**: Worker传递对象时序列化出现问题

**需要检查**:

- ColorValue的serialize()方法
- Worker到主线程的传递

## 🔧 高级调试

### 在控制台手动测试ColorValue

```javascript
// 测试CMYK到RGB转换
// 在浏览器控制台输入：

// Cyan 100%
const cyan = [1, 0, 0, 0];
const r = 255 * (1 - cyan[0]) * (1 - cyan[3]);
const g = 255 * (1 - cyan[1]) * (1 - cyan[3]);
const b = 255 * (1 - cyan[2]) * (1 - cyan[3]);
console.log(`CMYK [1,0,0,0] → RGB(${r}, ${g}, ${b})`);
// 应该输出: RGB(0, 255, 255) 即 #00ffff

// Magenta 100%
const magenta = [0, 1, 0, 0];
const r2 = 255 * (1 - magenta[0]) * (1 - magenta[3]);
const g2 = 255 * (1 - magenta[1]) * (1 - magenta[3]);
const b2 = 255 * (1 - magenta[2]) * (1 - magenta[3]);
console.log(`CMYK [0,1,0,0] → RGB(${r2}, ${g2}, ${b2})`);
// 应该输出: RGB(255, 0, 255) 即 #ff00ff
```
