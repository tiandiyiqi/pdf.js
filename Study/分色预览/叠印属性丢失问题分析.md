## 叠印(Overprint)技术背景

### 什么是叠印？

在印刷中，**叠印(Overprint)**是一种技术，允许一种颜色直接打印在另一种颜色之上，而不是镂空。

**示例**:

```
无叠印(默认):
  底层: Cyan 100%
  上层: Black 100% 文字
  → Black文字区域镂空，只打印Black

有叠印:
  底层: Cyan 100%
  上层: Black 100% 文字 (Overprint)
  → Black文字区域先打印Cyan，再打印Black
  → 颜色混合：Cyan + Black = 更深的黑色
```

### PDF中的叠印属性

PDF使用图形状态参数表示叠印：

- **OP**: 描边叠印(Overprint for stroke)
- **op**: 填充叠印(Overprint for fill)
- **OPM**: 叠印模式(Overprint mode)

## PDF.js中的叠印处理

### 原始实现(正确)

**evaluator.js 行1144-1149**:

```javascript
case "BM":
  // If we have overprint, override with darken blend mode
  if (hasOverprint) {
    gStateObj.push([key, "darken"]);  // ← 叠印转为Darken混合模式
  } else {
    gStateObj.push([key, normalizeBlendMode(value)]);
  }
  break;
```

**逻辑**:

1. 检测OP/op属性，设置`hasOverprint = true`
2. 当hasOverprint=true时，**强制设置BM为"darken"**
3. 这模拟了叠印的视觉效果（颜色叠加变暗）

**为什么用Darken模拟叠印？**

```
叠印效果 ≈ Darken混合模式

Cyan 100% + Black 100% (Overprint)
  ↓ 在CMYK空间
  C = max(1.0, 0) = 1.0
  M = max(0, 0) = 0
  Y = max(0, 0) = 0
  K = max(0, 1.0) = 1.0
  ↓ 结果
  CMYK [1.0, 0, 0, 1.0] = 非常深的青黑色
```

## 我们的修改导致的问题

### 问题代码(canvas.js 行1225-1247)

```javascript
case "BM":
  if (this.overprintOption) {
    // 检测CMYK颜色 + 非Normal混合模式
    const hasCMYKColor = ...;

    if (hasCMYKColor && value !== "source-over") {  // ← 问题在这里！
      warn(`CMYK blend mode "${value}" not yet supported.`);
      this.ctx.globalCompositeOperation = "source-over";  // ← 强制改为Normal
    }
  }
```

**问题流程**:

```
PDF文件: 设置OP=true (叠印)
  ↓
evaluator.js: hasOverprint=true → BM="darken"
  ↓
OperatorList: {fn: OPS.setGState, args: [["BM", "darken"]]}
  ↓
canvas.js: 检测到CMYK + "darken"
  ↓ 我们的修改
  检测: hasCMYKColor=true && value="darken" !== "source-over"
  ↓
  ❌ 发出警告："CMYK blend mode darken not supported"
  ❌ 强制改为"source-over"
  ↓
结果: 叠印效果丢失！
```

## 解决方案

### 方案1: 保留Darken用于叠印（推荐）

**原理**: Darken混合模式在RGB和CMYK空间的效果虽然不完全一致，但对于叠印模拟已经足够接近。

**修改canvas.js**:

```javascript
case "BM":
  if (this.overprintOption) {
    const hasCMYKColor = ...;

    // 特别处理：Darken用于叠印模拟，不应该被禁用
    if (hasCMYKColor && value !== "source-over" && value !== "darken") {
      warn(`CMYK blend mode "${value}" not yet supported.`);
      this.ctx.globalCompositeOperation = "source-over";
    } else {
      this.ctx.globalCompositeOperation = value;
      this.current.fillCompositeOperation = value;
      this.current.strokeCompositeOperation = value;
    }
  }
```

**优点**:

- ✅ 保留叠印效果
- ✅ 改动最小
- ✅ Darken在RGB空间的效果接近CMYK空间

**缺点**:

- ⚠️ Darken混合仍然在RGB空间（但对叠印来说可接受）

### 方案2: 完全禁用CMYK混合检测（不推荐）

**修改**:

```javascript
// 完全移除CMYK混合模式检测
case "BM":
  if (this.overprintOption) {
    this.ctx.globalCompositeOperation = value;
    this.current.fillCompositeOperation = value;
    this.current.strokeCompositeOperation = value;
  }
```

**优点**:

- ✅ 所有混合模式都工作

**缺点**:

- ❌ CMYK Lighten等混合模式结果错误
- ❌ 没有警告信息

### 方案3: 检测叠印来源（最佳，但复杂）

**思路**: 在OperatorList中传递叠印标记

**修改evaluator.js**:

```javascript
case "BM":
  if (hasOverprint) {
    gStateObj.push([key, "darken"]);
    gStateObj.push(["isOverprint", true]);  // ← 添加叠印标记
  } else {
    gStateObj.push([key, normalizeBlendMode(value)]);
  }
```

**修改canvas.js**:

```javascript
case "BM":
  if (this.overprintOption) {
    const hasCMYKColor = ...;
    const isOverprint = this.current.isOverprint;  // ← 检查叠印标记

    if (hasCMYKColor && value !== "source-over" && !isOverprint) {
      warn(`CMYK blend mode "${value}" not supported.`);
      this.ctx.globalCompositeOperation = "source-over";
    } else {
      this.ctx.globalCompositeOperation = value;
    }
  }
```

**优点**:

- ✅ 精确识别叠印
- ✅ 保留叠印效果
- ✅ 其他CMYK混合模式仍然被禁用

**缺点**:

- ❌ 需要修改更多代码
- ❌ 增加复杂度

## 色彩管理问题

### 预览层 vs 实际层

用户观察到：

- **预览层(ViewerX_Cyan)**: 颜色看起来正确，像经过色彩管理
- **实际层**: 颜色不准确，没有经过色彩管理

**可能原因**:

#### 1. 预览层使用Separation色彩空间

```javascript
// Separation色彩空间可能有自定义的tint函数
/Separation /Cyan /DeviceCMYK { dup dup dup }
```

**tint函数**可能包含色彩校正，使颜色更接近显示器的色域。

#### 2. 实际层使用DeviceCMYK

```javascript
/DeviceCMYK  // 直接使用CMYK值，没有色彩校正
```

我们的简化转换公式：

```javascript
R = 255 × (1 - C) × (1 - K)
G = 255 × (1 - M) × (1 - K)
B = 255 × (1 - Y) × (1 - K)
```

这是**设备相关**的转换，不考虑显示器色域和印刷色域的差异。

#### 3. 专业软件的做法

Adobe Acrobat等软件：

- 使用ICC色彩配置文件
- CMYK → Lab → RGB的转换路径
- 考虑输出意图(Rendering Intent)
- 黑点补偿(Black Point Compensation)

**我们缺少的**:

- ❌ ICC配置文件支持
- ❌ 色彩管理引擎(Color Management Module)
- ❌ 输出意图处理

## 过早RGB转换问题

### 当前架构

```
PDF内容
  ↓
evaluator.js: 创建ColorValue {colorSpace: 'CMYK', channels: [C,M,Y,K]}
  ↓
OperatorList传递
  ↓
canvas.js: colorValue.toRGB() → RGB "#RRGGBB"
  ↓ 此时已经是RGB了
ctx.fillStyle = "#RRGGBB"
  ↓
混合模式在RGB空间计算
```

**问题**: `toRGB()`在设置fillStyle时就调用了，混合时已经是RGB值。

### 理想架构

```
PDF内容
  ↓
evaluator.js: 保留CMYK
  ↓
canvas.js: 保留CMYK，不立即转RGB
  ↓
混合计算: 在CMYK空间进行
  ↓ 混合完成后
最终转RGB用于Canvas渲染
```

**需要**:

- 延迟RGB转换到混合之后
- 在CMYK空间进行混合计算
- 使用getImageData/putImageData像素级操作

**根本原因**: 我们的CMYK混合模式检测过于严格，将叠印用的"darken"也禁用了

1. 使用简化的CMYK→RGB转换

**解决方案**: 分阶段改进，从简单的公式优化到完整的CMS

**根本原因**: 架构设计，ColorValue在setFillStyle时就转RGB了

**解决方案**: 需要重新设计渲染流程，支持CMYK空间混合
