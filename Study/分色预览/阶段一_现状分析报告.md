**项目**: PDF.js CMYK+多专色透明度混合改造

**日期**: 2025年12月10日

## 执行摘要

本报告对PDF.js当前颜色处理流程进行了深度分析，精确验证了开发计划文档中提出的5个关键问题位置。分析确认：**当前实现在CMYK和DeviceN色彩空间处理中存在过早RGB转换和专色通道信息丢失的严重问题**，导致无法实现专业印刷预览功能。

### 关键发现

- ✅ 已验证全部5个问题位置的代码行号准确
- ⚠️ CMYK在解析阶段即转换为RGB，丢失原始通道信息
- 🔴 DeviceN专色通道在tint函数转换后完全丢失
- 🔴 混合模式在RGB空间计算，语义错误

## 问题位置详细分析

### 问题1: CMYK颜色过早转换为RGB

**位置**: `src/core/evaluator.js:2055-2064`

**问题代码**:

```javascript
// 行 2055-2058: setFillCMYKColor
case OPS.setFillCMYKColor:
  stateManager.state.fillColorSpace = ColorSpaceUtils.cmyk;
  args = [ColorSpaceUtils.cmyk.getRgbHex(args, 0)];  // ⚠️ 立即转换为RGB
  fn = OPS.setFillRGBColor;                          // ⚠️ 改变操作符类型
  break;

// 行 2060-2063: setStrokeCMYKColor
case OPS.setStrokeCMYKColor:
  stateManager.state.strokeColorSpace = ColorSpaceUtils.cmyk;
  args = [ColorSpaceUtils.cmyk.getRgbHex(args, 0)];  // ⚠️ 立即转换为RGB
  fn = OPS.setStrokeRGBColor;                        // ⚠️ 改变操作符类型
  break;
```

**问题分析**:

- **时机过早**: 在操作符列表构建阶段就转换，而非渲染阶段
- **信息丢失**: CMYK四通道值 [C, M, Y, K] 被合并为RGB三通道
- **操作符替换**: 原始的 `setFillCMYKColor` 被替换为 `setFillRGBColor`
- **后续影响**: 渲染层无法访问CMYK原始值，无法实现CMYK空间混合

**典型案例**:

```
输入: CMYK [0, 0, 0, 1.0] (100%黑)
转换: RGB #000000
输入: CMYK [1.0, 0, 0, 0] (100%青)
转换: RGB #00FFFF

Lighten混合:
  期望(CMYK空间): 白色 (因为K=0, C=0)
  实际(RGB空间): 青色 #00FFFF (max(#000000, #00FFFF))
```

### 问题2: DeviceN专色通道信息丢失

**位置**: `src/core/evaluator.js:2073-2079`

**问题代码**:

```javascript
// 行 2073-2079: setFillColorN
case OPS.setFillColorN:
  cs = stateManager.state.patternFillColorSpace;
  if (!cs) {
    if (isNumberArray(args, null)) {
      args = [ColorSpaceUtils.gray.getRgbHex(args, 0)];  // ⚠️ 转换为灰度RGB
      fn = OPS.setFillRGBColor;
      break;
    }
    // ...
  }
```

**相关位置**: `src/core/colorspace.js:357-367` (AlternateCS.getRgbItem)

```javascript
// AlternateCS类处理DeviceN/Separation色彩空间
getRgbItem(src, srcOffset, dest, destOffset) {
  const tmpBuf = this.tmpBuf;
  this.tintFn(src, srcOffset, tmpBuf, 0);     // ⚠️ 专色通过tint函数转换
  this.base.getRgbItem(tmpBuf, 0, dest, destOffset);  // ⚠️ 基础色空间转RGB
}
```

**信息流向**:

```
DeviceN [Cyan, Magenta, Yellow, Black, Spot1, Spot2, Spot3] (7通道)
    ↓ tintFn转换
CMYK [C, M, Y, K] (4通道) ← ⚠️ Spot1/Spot2/Spot3被合并到CMYK
    ↓ getRgbItem转换
RGB [R, G, B] (3通道) ← 🔴 专色通道信息完全丢失
```

**影响**:

- 🔴 **无法单独预览专色通道** (如Spot1、Spot2)
- 🔴 **无法实现专业印刷工作流**
- 🔴 **混合模式在错误的颜色空间计算**

**典型案例**:

```
场景: 图层1填充Cyan, 图层2填充Spot1, Lighten模式
期望: Cyan和Spot1分别保持，通道级独立混合
实际: 两者都转为RGB后混合，Spot1信息丢失
```

### 问题3: 混合模式映射不当

**位置**: `src/core/evaluator.js:122-181` (normalizeBlendMode函数)

**问题代码**:

```javascript
function normalizeBlendMode(value, parsingArray = false) {
  // ...
  switch (value.name) {
    case "Normal":
    case "Compatible":
      return "source-over";
    case "Lighten":
      return "lighten"; // ⚠️ 直接映射到Canvas lighten (RGB空间)
    case "Darken":
      return "darken"; // ⚠️ 直接映射到Canvas darken (RGB空间)
    // ...
  }
}
```

**问题分析**:

- PDF Lighten模式定义在原始颜色空间中工作（可能是CMYK或DeviceN）
- Canvas lighten模式在RGB空间中工作
- **语义不匹配**: CMYK Lighten ≠ RGB Lighten

**CMYK vs RGB Lighten差异**:

```
CMYK Lighten算法:
  result = min(C1, C2), min(M1, M2), min(Y1, Y2), min(K1, K2)
  (取最小值，因为CMYK是减色系统)

RGB Lighten算法:
  result = max(R1, R2), max(G1, G2), max(B1, B2)
  (取最大值，因为RGB是加色系统)
```

### 问题4: 颜色空间信息未传递

**位置**: `src/display/canvas.js:2470-2474`

**问题代码**:

```javascript
setFillRGBColor(opIdx, color) {
  this.dependencyTracker?.recordSimpleData("fillColor", opIdx);
  this.ctx.fillStyle = this.current.fillColor = color;  // ⚠️ 只接收RGB颜色字符串
  this.current.patternFill = false;
}
```

**问题分析**:

- 渲染层只接收RGB颜色字符串 (如 "#FF0000")
- **无法访问原始颜色空间信息** (CMYK、DeviceN)
- **无法判断应该使用何种混合算法**

**缺失信息**:

```javascript
// 当前传递的信息
color = "#00FFFF"  // 仅RGB值

// 需要传递的信息
{
  colorSpace: 'DeviceN',
  channels: {
    cmyk: [1.0, 0, 0, 0],
    spots: {
      'Spot1': 0.5,
      'Spot2': 0.8
    }
  },
  rgbFallback: "#00FFFF"  // 用于不支持的场景
}
```

### 问题5: DeviceN色彩空间解析不足

**位置**: `src/core/colorspace_utils.js:256-261`

**问题代码**:

```javascript
case "Separation":
case "DeviceN":
  const name = xref.fetchIfRef(cs[1]);
  numComps = Array.isArray(name) ? name.length : 1;
  baseCS = this.#subParse(cs[2], options);
```

**问题分析**:

```javascript
new AlternateCS((numComps = 7), baseCS, tintFn);

new DeviceNCS({

    "Cyan",
    "Magenta",
    "Yellow",
    "Black",
    "Spot1",
    "Spot2",
    "Spot3",
  ],
```
